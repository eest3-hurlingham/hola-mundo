Antes de empezar

Verificá que tenés todo lo necesario antes de arrancar.

✅ Lista de verificación
  • Python instalado — verificalo con python --version en la terminal
  • Git instalado y configurado con tu nombre y mail
  • VS Code instalado y abierto
  • La terminal abierta — en Windows: "Símbolo del sistema". En Mac: "Terminal"
🚨 ¿Python no se reconoce en Windows?
Probá con py --version en lugar de python --version. Si tampoco funciona, avisale al profe.
2

Clonar el proyecto y levantar el servidor

Primero clonás el proyecto desde GitHub y después lo levantás. Seguí los pasos según tu sistema operativo.

cmd — Windows 
git clone https://github.com/eest3-hurlingham/hola-mundo.git
cd hola-mundo
python -m venv venv
venv\Scripts\activate
pip install django
python manage.py runserver
Terminal — Mac 
git clone https://github.com/eest3-hurlingham/hola-mundo.git
cd hola-mundo
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python manage.py runserver
✅ ¿Cómo sé que funcionó?
Cuando el servidor está corriendo vas a ver en la terminal: Starting development server at http://127.0.0.1:8000/. Abrí esa dirección en el navegador.
⚠️ El (venv) es importante
Cuando el entorno virtual está activo, el prompt muestra (venv) al principio. Si no lo ves, el entorno no está activo y los comandos no van a funcionar.
⚠️ No cerrés la terminal
El servidor corre en la terminal mientras trabajás. Para detenerlo usá Ctrl + C. Para abrir el editor sin cerrar el servidor, abrí una terminal nueva.
3

¿Cómo funciona Django?

Antes de tocar el código, entendé qué pasa cada vez que escribís una URL en el navegador. Son siempre tres pasos en orden:

urls.py
¿Quién atiende
esta URL?
→
views.py
Proceso los datos
y preparo la respuesta
→
template.html
Muestro el resultado
al usuario

Este ciclo URL → View → Template se repite en cada página del sistema. Si lo entendés, entendiste Django.

💡 Un ejemplo concreto
Cuando escribís /saludo/maximiliano/ en el navegador:
1. urls.py dice: "esta URL la atiende la función saludo()"
2. views.py: la función recibe "maximiliano" y prepara los datos
3. saludo.html: muestra "Hola, Maximiliano! 👋" en la pantalla
4

Explorando urls.py

Abrí el proyecto en VS Code. Vas a ver esta estructura de archivos:

holamundo/
  holamundo/ ← configuración del proyecto
    urls.py ← PASO 1: distribuye las URLs
    settings.py
  saludo/ ← la app
    urls.py ← PASO 2: asigna funciones a URLs
    views.py ← PASO 3: la lógica
  templates/
    base.html ← estructura compartida
    saludo/
      inicio.html ← PASO 4: lo que ve el usuario
      saludo.html
  manage.py

holamundo/urls.py — el distribuidor central

Abrí holamundo/urls.py. Vas a ver algo así:

holamundo/urls.py
from django.urls import path, include

urlpatterns = [
    path('', include('saludo.urls')),
]

Las comillas simples vacías '' significan "cualquier URL que llegue". Django la manda a saludo.urls para que la atienda.

saludo/urls.py — las URLs de la app

Ahora abrí saludo/urls.py:

saludo/urls.py
urlpatterns = [
    path('', views.inicio, name='inicio'),
    path('saludo/<str:nombre>/', views.saludo, name='saludo'),
]

Hay dos URLs definidas:

  • '' → URL vacía (/) → llama a la función inicio()
  • 'saludo/<str:nombre>/' → por ejemplo /saludo/ana/ → llama a saludo() y le pasa nombre='ana'
💡 ¿Cómo elige Django cuál URL usar?
Recorre la lista de arriba hacia abajo y compara la URL con cada patrón. Cuando encuentra una que coincide, llama a la función correspondiente y para de buscar.
5

Explorando views.py

Abrí saludo/views.py. Acá están las funciones que procesan cada pedido.

A
La función inicio() — sin parámetros ▶
saludo/views.py
def inicio(request):
    return render(request, 'saludo/inicio.html')

Esta función solo recibe request (el pedido del navegador) y le dice a Django que muestre el template inicio.html. Sin datos extras.

B
La función saludo() — con parámetro de la URL ▶
saludo/views.py
def saludo(request, nombre):
    contexto = {
        'nombre': nombre,
        'mensaje': '¡Bienvenido a Django!',
    }
    return render(request, 'saludo/saludo.html', contexto)

Esta función recibe request y también nombre — que vino de la URL. Prepara un diccionario llamado contexto con los datos que quiere pasar al template, y se lo manda junto con el render.

💡 ¿Qué es el contexto?
Es un diccionario Python que conecta la view con el template. Todo lo que ponés acá lo podés usar en el HTML con {{ nombre }} y {{ mensaje }}.
6

Explorando los templates

A
base.html — la estructura compartida ▶

Abrí templates/base.html. Este es el template que comparten todas las páginas del sitio. Tiene el encabezado, el menú y los estilos CSS.

Buscá estas dos líneas clave:

templates/base.html
<title>{% block titulo %}Mi primer proyecto Django{% endblock %}</title>

{% block contenido %}
{% endblock %}

Los {% block %} son espacios reservados — los templates hijos los rellenan con su propio contenido. Si un hijo no los sobreescribe, se muestra el valor por defecto.

⚠️ No modificar este archivo
base.html es la estructura compartida de todo el sitio. Si lo modificás afectás a todas las páginas.
B
saludo.html — el template hijo ▶

Abrí templates/saludo/saludo.html:

templates/saludo/saludo.html
{% extends "base.html" %}

{% block titulo %}Saludo a {{ nombre }}{% endblock %}

{% block contenido %}
    <h2>{{ mensaje }}</h2>
    <h3>Hola, {{ nombre }}! 👋</h3>
{% endblock %}

Tres conceptos nuevos:

  • {% extends "base.html" %} — hereda toda la estructura de base.html
  • {% block contenido %} — rellena el bloque que base.html dejó vacío
  • {{ nombre }} — muestra el valor que vino del contexto en views.py
✅ El ciclo completo
/saludo/ana/ → urls.py llama a saludo() → views.py pone "ana" en el contexto → saludo.html muestra "Hola, Ana! 👋"

Probarlo y modificarlo

Con el servidor corriendo, probá estas tres cosas en el navegador:

1
Probá con tu nombre en la URL ▶

Reemplazá tunombre con tu nombre real:

URL — navegador
http://127.0.0.1:8000/saludo/tunombre/

¿Qué aparece en la pantalla? ¿Y en la pestaña del navegador? ¿De dónde vino tu nombre?

2
Cambiá el mensaje en views.py ▶

Abrí saludo/views.py y cambiá el mensaje:

saludo/views.py
'mensaje': '¡Hola desde el SGE!',  # cambiá este texto

Guardá el archivo con Ctrl+S (Windows) o Cmd+S (Mac) y recargá el navegador. No hace falta reiniciar el servidor — Django detecta el cambio automáticamente.

✅ ¿Cambió el mensaje?
Si ves el nuevo texto en la pantalla, significa que entendiste la conexión entre views.py y el template. ¡Bien!
3
Agregá un dato nuevo al contexto ▶

En views.py agregá una clave nueva al contexto:

saludo/views.py
contexto = {
    'nombre': nombre,
    'mensaje': '¡Bienvenido!',
    'modulo': 'Gestión de Alumnos',  # nuevo
}

Luego en saludo.html mostralo con:

templates/saludo/saludo.html
<p>Módulo: {{ modulo }}</p>

Guardá los dos archivos y recargá. ¿Aparece el módulo en la pantalla?

🚀 Desafío: creá tu propia página

Usando exactamente lo que aprendiste, creá una nueva página para el módulo de tu grupo. Tenés que tocar tres archivos — uno por cada parte del ciclo.

  • En saludo/views.py — agregá una función nueva (ej: def alumnos(request)) con un contexto que tenga el nombre de tu módulo y una lista hardcodeada de datos de ejemplo
  • En saludo/urls.py — registrá la URL nueva (ej: path('alumnos/', views.alumnos, name='alumnos'))
  • En templates/saludo/ — creá un archivo nuevo (ej: alumnos.html) que extienda base.html y muestre los datos del contexto
💡 Pista: cómo mostrar una lista

En views.py:

views.py
contexto = {
    'titulo': 'Gestión de Alumnos',
    'lista': ['Ana García', 'Bruno López', 'Carla Ruiz']
}

En el template:

template.html
<h1>{{ titulo }}</h1>
{% for item in lista %}
    <p>{{ item }}</p>
{% endfor %}
⚠️ Si algo no funciona
Leé el error que muestra Django en el navegador — es muy descriptivo. Los errores más comunes son: nombre del template mal escrito, olvidarse del {% endfor %}, o no guardar el archivo antes de recargar.
